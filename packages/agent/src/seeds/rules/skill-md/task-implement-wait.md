Start `nodespace wait node <task-id> --until '[{"type":"property","operator":"equals","property":"status","value":"in_review","negate":true}]' --unless '[{"type":"property","operator":"equals","property":"status","value":"cancelled"}]'` as a background command and end your turn: it exits when the task leaves `in_review`, and your harness resumes you. Exit 0 prints the task as `node context` reads it, with its status and its `version`. Exit 3 is the wait's timeout and exit 5 an unavailable daemon: run the same command again, nothing is lost. Exit 4 means the task was cancelled or deleted: stop and tell the user. In a harness that cannot run a command in the background, do not wait: tell the user to come back when the review is in, then read the task with `nodespace node context <task-id>`.
