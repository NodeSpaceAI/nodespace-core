Run `nodespace node create --type checkbox --parent <id> --content "- [ ] <condition>"` once per item, with the id of the node the item belongs under. A criterion goes directly under its spec or task, or under that node's `## Acceptance Criteria` header (create the header first when it has none with `--type header --content "## Acceptance Criteria"`, then give its id as the parent). The rules for finishing a task and approving a spec count both places; the search for ready tasks lists a task only by the checkboxes directly under it. When the node is being created in this same step, the items can go in its create call instead, as `- [ ] <condition>` lines in the single-quoted markdown document of `--content`, with the title as the first line, then the items, before any `##` header line, or, for criteria, as the lines under an `## Acceptance Criteria` line. If that call fails as unimplemented, tell the user to update NodeSpace and stop.
