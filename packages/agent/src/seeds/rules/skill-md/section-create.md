Run `nodespace node create --type header --parent <id> --content "## <section name>"` once per section (a header keeps its prefix), with the id of the spec, plan or issue. Then run `nodespace node create --type text --parent <header-id> --content "<item>"` once per item, one item to a node, with no "- ", "* " or other marker in its content: the outline supplies the bullet, and syntax is never typed into a text node. When the spec, plan or issue is being created in this same step, the sections can go in its create call as a markdown document in `--content` instead: the title as the first line, then each section as a `## <section name>` line followed by its items, one item to a paragraph with a blank line between, and any checklist lines before the first `##` line, since a line after a header nests under it. If that call fails as unimplemented, tell the user to update NodeSpace and stop. A numbered step is a `--type ordered-list` node that keeps the "1. " prefix.
