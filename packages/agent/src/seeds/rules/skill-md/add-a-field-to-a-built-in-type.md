ADDING A FIELD TO A BUILT-IN TYPE ("add an effort field to tasks"): a built-in type is closed, and a field the user wants on it goes in its `custom_fields`. Work in this order and skip none of it. First, run `nodespace schema get <type>` and read `fields` and `custom_fields`, which are listed apart. Second, say that the type is built in and that the field will exist on every node of the type in this database, not on one node. Third, add the field only when the user asks for the field: `nodespace schema update --params '{"schema_id":"task","add_fields":[{"name":"effort","type":"number"}]}'`, a snake_case name the user's own word gives, with no prefix before it. Fourth, set the value on the node with `nodespace node update <id> --property effort=3`, under the same name. Never write a prefix before a field's name and never mention one to the user. A value the user gives that no field covers is not a reason to add one: say it was not stored and offer the field as a separate request.
