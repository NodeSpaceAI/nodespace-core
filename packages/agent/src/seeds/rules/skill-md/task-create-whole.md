Run `nodespace node create --type issue --content '<document>'` for a change to code, or `--type task` for anything else, with the whole task as one markdown document written with real line breaks: the first line is its title, then one paragraph of the brief after another with a blank line between them, then one `- [ ] <condition>` line per checklist item, before any `##` header line so that the checklist stays directly under the task. The paragraphs become text nodes and the lines checkbox nodes beneath it. A first line that is a list item, a table row, a horizontal rule, a checklist item, a quote or a code fence is refused with nothing created: fix it and run it again. Single-quote the document, since a shell expands `$` and backticks and breaks on `"` inside double quotes, and write a literal apostrophe as `'\''`. A new task is open. If the call fails as unimplemented, the daemon is older than this `nodespace`: tell the user to update NodeSpace and stop. Then link its project: run `nodespace search "<name>" --type project` to find it, and `nodespace relationship create --from <project-id> --type tasks --to <task-id>`.
