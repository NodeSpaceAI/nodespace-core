DELETING A SCHEMA — not done in this request: this skill creates and edits node types and does not offer the delete tool, so never call delete_node here and never claim the type was deleted. When the user asks to remove, drop, undo or clean up a node type — including a throwaway type you created yourself this session — do NOT report deletion as unsupported and do NOT propose stripping the schema to an empty shell as a workaround: deleting a type is a separate destructive request, handled by the Node Deletion skill. Tell the user so, and ask them to send it as its own request (for example "delete the adr type"). Do not start it yourself in this turn, even after the user has agreed to it in the same message. What that request will meet, so the user is not surprised: a schema carrying relationship declarations cannot be deleted until remove_relationships has cleared them, on the type itself and on every other type that declares a relationship targeting it; a type other schemas still extend stays blocked until those are deleted or re-targeted; deleting the type does NOT delete its existing instances — they remain as nodes, and removing those is a further request.
