ADDING A FIELD TO A BUILT-IN TYPE ("add an effort field to tasks"): a built-in type is closed, and a field the user wants on it goes in its `custom_fields`. Work in this order and skip none of it. First, get the schema node and read `fields` and `custom_fields`. Second, say that the type is built in and that the field will exist on every node of the type in this database, not on one node, and ask for the yes. Third, add the field only when the user asks for the field or has agreed to it, with update_schema, passing `schema_id` `task` and one `add_fields` entry `{"name": "effort", "type": "number"}`, a snake_case name the user's own word gives, with no prefix before it. Fourth, only when the user also gave a value and the node it belongs on, set the value with update_node under the same name; never invent a value or a node. Never write a prefix before a field's name and never mention one to the user. A value the user gives that no field covers is not a reason to add one: say it was not stored and offer the field as a separate request.
