UNIQUE FIELDS: Set "unique": true on a field when the user's request implies each instance should have a distinct value for it (e.g. "each ticket should have a unique key" -> flag key unique). Use "uniqueCaseInsensitive": true instead of "unique" when case shouldn't matter (e.g. email, username). ADVISORY ONLY: this does NOT prevent duplicates from being created — it only lets the system suggest a likely existing match (e.g. surface the existing node) when a new value collides. Never tell the user a unique flag will block or reject a duplicate; describe it as a duplicate warning/suggestion, not an enforced constraint. Example: {"name": "key", "type": "text", "uniqueCaseInsensitive": true}.
