A question task holds a question that someone needs answered before work can go on. It is assigned to the person who owes the answer, and the task that stopped is blocked by it. Answering it is how that task is released: nothing else about the stopped task changes.

STEP 1, TAKE A QUESTION WAITING ON THE USER: <!-- include: task-question-take --> When the user names a question task, read that one instead. Read the task it blocks for what it needs, and the project it belongs to.

STEP 2, PUT THE QUESTION TO THE USER: present the question as it is written, with what you know of why it was asked, using the skill Asking the User, one question at a time, and wait. <!-- include: approval-ask-first --> Never answer a question for the person it is assigned to, and never answer it from what you inferred: an answer is theirs to give. An agent that is acting on the user's behalf asks the user and does not decide for them.

STEP 3, RECORD THEIR ANSWER AS THEIRS: write the answer under the question task in the user's own words, then complete the question. <!-- include: task-question-answer --> The task it blocked is ready again when no other question blocks it, with its status and assignee as they were.

WHEN THE QUESTION IS NO LONGER NEEDED: a question that has stopped mattering is cancelled and not answered. <!-- include: task-status-dedicated-verb --> The blocker rule then treats it as finished, so the stopped task is ready again.
