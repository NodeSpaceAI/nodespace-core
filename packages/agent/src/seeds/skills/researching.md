This is the procedure for a question whose answer is a fact that has to be found in sources outside the conversation: how a library behaves, what a standard requires, what the code does today. It ends in an answer with its sources, written down where the user can find it. When the answer is the user's own preference, use Asking the User. When the answer is already in the user's own notes and records, searching them is enough and needs no procedure. When running code would answer it faster than reading, use Prototyping.

STEP 1, STATE THE QUESTION AND WHAT WOULD COUNT AS AN ANSWER: write the question so that it has an answer a source can give, and say what the answer will be used for. A question too wide to answer is split, and the parts are researched in turn.

STEP 2, LOOK IN THE USER'S RECORDS FIRST: <!-- include: ask-look-up --> <!-- include: decision-find-first --> A decision or a note already answers some questions, and says what was turned down and why.

STEP 3, GO TO PRIMARY SOURCES: the code itself, the specification, the vendor's own documentation, the change record of the thing in question. A summary, a forum answer or a recollection is a lead to a primary source and not an answer. Read the version the project uses, and say which it is.

STEP 4, WRITE EACH CLAIM WITH ITS SOURCE: every statement of fact carries where it came from, with enough to find it again: the document and section, or the file and line. What you inferred is marked as inferred, and what you could not find is said to be not found. Two sources that disagree are both stated, and the disagreement is the finding. Never fill a gap with what is probably true.

STEP 5, END IN A RECORD, NEVER IN UNTRACKED OUTPUT: write the answer where the user said it goes. When they named a node, add the note under it: <!-- include: section-create --> When the answer settles a choice, record it as a decision with the sources cited in its body, following Recording a Decision. <!-- include: decision-create --> When the user named no place, ask where it belongs with Asking the User and write nothing until they say. The research is not finished while the answer exists only in the conversation.

WHEN DONE: tell the user the answer in a few sentences, how sure it is, what was inferred or not found, and where the record with its sources was written.
