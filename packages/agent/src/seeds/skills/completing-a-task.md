A task is finished when its checklist is: every checkbox directly under it is checked. Marking it done is the last write to a task, and the one the rules guard most.

READ THE TASK FIRST: <!-- include: task-complete-read -->

EVERY ITEM IS CHECKED BEFORE IT IS DONE: a task with an unchecked item cannot be marked done, whatever kind of task it is. Do not tick an item to get past this. An item is ticked when it is met, with what shows it written beneath it. An item that is not met is work still to do, and an item that no longer applies is the user's to remove, not yours.

A TASK UNDER A SPEC OR A PLAN NEEDS A CHECKLIST: such a task with no checkbox at all cannot be marked done. Its checklist is written from the spec's criteria when the plan is broken into tasks: write it and then meet it, never the reverse. A task with no spec, no plan and no checklist is an ordinary to-do, and is simply marked done.

MARK IT DONE: <!-- include: task-complete-done --> A task waiting for review is marked done by its reviewer, not by whoever did the work.

WHAT A REJECTION MEANS: the message names the cause, and each cause has one fix.
- An unchecked item: finish that item, or tell the user it cannot be met.
- No checklist on a task under a spec or a plan: write the checklist from the spec's criteria.
- The task's plan is not approved, or the task is not linked to its plan's spec: the plan's approval is the user's to give, and the missing link is made from the spec to the task.
- A task it is blocked by is not finished: this stops a task being started or put in review, and the blocker is finished or cancelled first.
